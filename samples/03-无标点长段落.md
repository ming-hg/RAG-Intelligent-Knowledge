# 无标点长段落（实测样本 C）

这一段故意只用逗号连接、整段几乎没有句号，用来验证语义切分在找不到足够分隔符时退回定长窗口切分，并检查相邻块之间是否真的留了 60 字重叠。
下午的评审从队列说起，先说入库 worker 的并发为什么固定成一，因为这台机器只有一张卡，把并发改成二并不会让总时间变短，只会让两次 embedding 请求同时挤在一个端口上排队，排队时间超过九十秒就撞超时，超时之后退避重试，重试又接着排队，看起来像是模型服务变慢了其实是自己把自己堵住了，所以并发这条配置在单机部署下应该写成一并且不许改，除非换了多卡机器并且同时把 LM Studio 的并行请求上限也调开；接着说租约为什么是十分钟而不是三十秒，租约太短会让一个正在跑大文件入库的 worker 在半路被别人抢走任务，两个 worker 同时写同一篇文档的同一个代次就会出现主键冲突，冲突之后回滚，回滚之后重新排队，重新排队又抢一半，这种循环能一直转到天黑，所以租约必须大于最慢一篇文档的正常入库时间，实测最大的一篇 pdf 是六分二十秒，取十分钟留一倍余量；然后说预览接口为什么不写库，因为调分块参数这件事的本质是试，试就要能反复试，每次试都往库里写一份垃圾块的话，检索就会在试的这段时间里召回这些没人负责的块，而且试完之后还得手工删，删漏一次就永久留在库里，所以预览只算不写，真正生效必须显式点保存并且触发一次重算；最后说引用跳转为什么要带页码和字偏移两套坐标，因为 pdf 的页码对纯文本和 markdown 完全没有意义，而字符偏移对扫描件的排版又毫无办法，两套都留着才能在界面上说一句人话，比如第三页第一千二百四十到一千六百二十字，而不是只显示一个内部编号，评审记录到这里告一段落，本段末尾的校验码是 TAIL-9F3C，能在检索里搜到 TAIL-9F3C 就说明段落尾部没有被切分丢掉。
